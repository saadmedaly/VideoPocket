# VideoPocket

منصة ويب عربية (RTL) لتنزيل فيديوهات يوتيوب العامة بصيغة MP4 (صوت + صورة) على الهاتف، عبر الشبكة المحلية.

**للاستخدام الشخصي فقط** بفيديوهات تملكها أو لديك إذن بتنزيلها. لا يتجاوز هذا المشروع أي حماية DRM أو قيود وصول أو محتوى خاص/مدفوع.

## البنية

```
backend/    FastAPI + yt-dlp + FFmpeg — خادم التحليل والتنزيل (طابور + عامل خلفي + SQLite)
frontend/   صفحة HTML/CSS/JS عربية RTL بسيطة
```

## التشغيل المحلي (Windows)

### المتطلبات
- Python 3.11+ (تم التطوير والاختبار على 3.13)
- FFmpeg و ffprobe على PATH (تحقق بـ `ffmpeg -version`)

### 1. تشغيل الخادم (Backend)

```powershell
cd backend
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m uvicorn main:app --host 0.0.0.0 --port 8200
```

لإتاحة الوصول من الهاتف عبر الشبكة نفسها، اضبط `ALLOWED_ORIGINS` ليشمل عنوان جهازك على الشبكة (انظر أدناه):

```powershell
$env:ALLOWED_ORIGINS="http://127.0.0.1:5500,http://localhost:5500,http://<عنوان-جهازك>:5500"
.venv\Scripts\python.exe -m uvicorn main:app --host 0.0.0.0 --port 8200
```

### 2. تشغيل الواجهة (Frontend)

في نافذة طرفية أخرى:

```powershell
cd frontend
python -m http.server 5500 --bind 0.0.0.0
```

### 3. معرفة عنوان جهازك على الشبكة

```powershell
ipconfig
```

ابحث عن "Adresse IPv4" (أو IPv4 Address) تحت بطاقة Wi-Fi النشطة (مثال: `192.168.100.20`). تجاهل عناوين VirtualBox/VMware الافتراضية.

### 4. الفتح من الهاتف

- تأكد أن الهاتف والحاسوب متصلان **بنفس شبكة Wi-Fi**.
- افتح على الهاتف: `http://<عنوان-جهازك>:5500` (مثال: `http://192.168.100.20:5500`)
- الواجهة تتصل تلقائيًا بالخادم على نفس العنوان، المنفذ `8200`.
- يجب أن يبقى الحاسوب والخادم يعملان طوال فترة الاستخدام.

**ملاحظة:** لا تستخدم `localhost` من الهاتف — هذا سيشير إلى الهاتف نفسه، لا إلى حاسوبك.

### إيقاف الخدمة

أوقف العمليتين بـ `Ctrl+C` في كل نافذة طرفية.

## متغيرات البيئة (Backend)

انظر `backend/.env.example` للقائمة الكاملة. الأهم:

| المتغير | الوصف | الافتراضي |
|---|---|---|
| `ALLOWED_ORIGINS` | قائمة الأصول المسموح لها بالاتصال (CORS) | `http://127.0.0.1:5500,http://localhost:5500` |
| `PORT` | منفذ الخادم | `8200` |
| `ACCESS_TOKEN` | رمز دخول اختياري لحماية الخدمة عند نشرها على الإنترنت | (فارغ) |
| `MAX_VIDEO_DURATION` | أقصى مدة فيديو مسموح بها (ثوانٍ) | `10800` (3 ساعات) |
| `MAX_DOWNLOAD_SIZE` | أقصى حجم ملف نهائي (بايت) | `1610612736` (1.5 ج.ب) |
| `DOWNLOAD_TIMEOUT` | أقصى مدة لعملية تنزيل واحدة (ثوانٍ) | `2700` (45 دقيقة) |
| `FILE_RETENTION_SECONDS` | مدة صلاحية الملف الجاهز قبل حذفه | `3600` (ساعة) |
| `DOWNLOAD_WORKERS` | عدد عمليات التنزيل المتزامنة | `1` |

هذه القيم افتراضات معقولة لجهاز شخصي عادي؛ عدّلها حسب موارد جهازك الفعلية.

## كيف يعمل تنزيل الفيديوهات الطويلة

- الطلب يُنشئ "مهمة" (job) في قاعدة بيانات SQLite محلية، ويعود فورًا برقم تعريف المهمة.
- عامل خلفي واحد (قابل للزيادة عبر `DOWNLOAD_WORKERS`) يسحب المهام من طابور ويعالجها بالتتابع.
- yt-dlp ينزّل إلى القرص تدريجيًا (لا يُحمَّل الفيديو في الذاكرة)، ثم يدمج الصوت والصورة بصيغة MP4 عبر FFmpeg على الخادم.
- الواجهة تستطلع حالة المهمة كل 1.5 ثانية وتعرض: الانتظار، جلب المعلومات، التنزيل (مع النسبة والسرعة والوقت المتبقي الفعليين من yt-dlp)، الدمج، جاهز، فشل، أُلغي.
- بعد إعادة تشغيل الخادم، أي مهمة كانت منقطعة أثناء المعالجة تُعلَّم تلقائيًا بأنها "فشل" (`interrupted_by_restart`) بدل أن تبقى معلّقة إلى الأبد.
- الملفات الجاهزة تُحذف تلقائيًا بعد ساعة (قابل للتعديل)، وكذلك أي مجلدات متبقية من مهام فاشلة أو ملغاة أو من عمليات متوقفة بشكل غير متوقع.

## القيود الحالية

- **دعم يوتيوب فقط.** لا TikTok ولا Instagram ولا منصات أخرى في هذه النسخة.
- **فيديو واحد فقط لكل رابط** — لا قوائم تشغيل، لا بث مباشر جارٍ، لا محتوى خاص.
- **لا حدّ تعسفي بـ 30 دقيقة**، لكن الحد العملي (3 ساعات / 1.5 ج.ب افتراضيًا) قابل للتعديل حسب موارد جهازك عبر متغيرات البيئة أعلاه — فيديو طويل جدًا جدًا (مثل بث كامل لعدة ساعات) قد يحتاج رفع هذه القيم ومساحة قرص كافية.
- **عامل تنزيل واحد افتراضيًا** — تنزيلان طويلان متزامنان سيُعالَجان بالتتابع، لا بالتوازي (قابل للتغيير عبر `DOWNLOAD_WORKERS` لكن هذا يستهلك نطاقًا ترددًا ومعالجة أكبر).
- **يعمل محليًا عبر شبكة Wi-Fi فقط في هذا التسليم** — لم يُنشر على استضافة مجانية خارجية (انظر السبب أدناه).
- **لا دعم لنقل مستمر في الخلفية**: إذا أُغلق المتصفح أثناء نقل الملف نفسه (بعد الضغط على "حفظ الفيديو")، ينقطع النقل؛ أما تقدّم التنزيل على الخادم فمستمر بشكل مستقل ولا يتأثر بإغلاق المتصفح قبل جاهزية الملف.
- **الصيغة النهائية mp4** مع ترميز الفيديو والصوت كما يوفرهما يوتيوب (av1/vp9 + aac غالبًا) دون إعادة ترميز إضافية، لتفادي معالجة ثقيلة بلا حدود — الملف يعمل على مشغلات الهاتف الحديثة.

## لماذا لا يوجد نشر خارجي في هذا التسليم

لم أنشر الخدمة على استضافة سحابية مجانية في هذه الجولة. السبب العملي المعروف من مشروع مشابه في هذا الجهاز (Video-Saver): مزودات الاستضافة المجانية الشائعة (مثل Render) تُحجب أحيانًا من طرف يوتيوب كمحاولات بوت `Sign in to confirm you're not a bot` بسبب نطاقات IP الخاصة بمراكز البيانات، وهذه مشكلة من طرف يوتيوب لا تُحل بأدوات تجاوز (لم أستخدم أي كوكيز أو بروكسي أو خدمة تجاوز). التشغيل محليًا عبر Wi-Fi يتجنّب هذه المشكلة تمامًا لأن الطلبات تنطلق من عنوان منزلي عادي، وهذا ما تم تسليمه وتم اختباره فعليًا بنجاح.

إذا احتجت نشرًا خارجيًا لاحقًا، يمكن تجربة مزود يسمح بعناوين IP غير محجوبة من يوتيوب (مثل Railway في تجربة المشروع المشابه) ضمن الحدود المجانية لذلك المزود — لكن هذا يتطلب اختبارًا فعليًا من بيئة النشر نفسها قبل اعتماده كحل ناجح.

## تأكيد

لم يتم تفعيل أي خدمة مدفوعة أو اشتراك أو بطاقة بنكية في أي جزء من هذا العمل. كل المكتبات المستخدمة (FastAPI، yt-dlp، FFmpeg) مجانية ومفتوحة المصدر، والتشغيل محلي بالكامل.
